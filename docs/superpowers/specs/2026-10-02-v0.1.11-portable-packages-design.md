# v0.1.11 portable packages and bilingual READMEs

## Objective

Complete release v0.1.11 with portable ZIP packages for Windows and macOS,
bilingual quick-start READMEs, and operating-system-aware connection commands.
The existing macOS DMG remains available.

## Connection command selection

The “Conectar” screen will choose its initial shell from the browser platform:

- Windows defaults to `Windows PowerShell` and generates
  `$env:OLLAMA_HOST="..."`.
- macOS and Linux default to `macOS / Linux` and generate
  `export OLLAMA_HOST=...`.
- Unknown platforms keep the current POSIX fallback.

The shell selector remains visible and users can always override the detected
default. Detection will be isolated in a pure frontend helper so it can be
tested independently. It will not change saved application settings or require
backend access.

## Windows package

`OllamaConfigurator-Windows-x64.zip` will contain at its root:

- `README.md`
- `install.ps1`
- `run.ps1`
- `uninstall.ps1`
- `backend/`
- `frontend/`

The Windows README will contain complete Portuguese and English sections. It
will explain how to extract the archive, open PowerShell in the extracted
folder, allow scripts for the current PowerShell process, install, run, and
uninstall the application.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\install.ps1
.\run.ps1
```

It will state that installation defaults to
`%LOCALAPPDATA%\Ollama Configurator`, port 8787 serves the interface, and port
11435 serves the Ollama gateway. It will explain that an existing Configurator
instance may be replaced automatically, while an unrelated process is
preserved and identified.

## macOS portable package

`OllamaConfigurator-macOS-arm64.zip` will contain at its root:

- `Ollama Configurator.app`
- `README.md`

The macOS README will contain complete Portuguese and English sections. It will
identify the package as Apple Silicon (`arm64`) and explain both Finder and
Terminal installation. The recommended terminal installation is user-local and
does not require administrator privileges:

```bash
mkdir -p "$HOME/Applications"
ditto "Ollama Configurator.app" "$HOME/Applications/Ollama Configurator.app"
open "$HOME/Applications/Ollama Configurator.app"
```

It will also explain direct portable execution with
`open "Ollama Configurator.app"`, and clarify that the DMG remains the standard
graphical installation option. The README will not instruct users to disable
Gatekeeper or remove quarantine attributes.

## Build and release flow

The Windows workflow remains manually triggered and builds on a Windows runner.
It creates the ZIP and `checksums-Windows.txt` for upload to the existing
v0.1.11 release.

The macOS workflow will additionally package the already-built `.app` and its
README into a ZIP using `ditto`, preserving the application bundle structure.
It generates checksums for both the DMG and ZIP. Existing macOS assets remain
available, with updated checksum metadata uploaded to v0.1.11.

Before upload, each workflow will inspect its archive and verify the required
README and runtime entries. The release will contain:

- `OllamaConfigurator-macOS.dmg`
- `OllamaConfigurator-macOS-arm64.zip`
- `checksums-macOS.txt`
- `OllamaConfigurator-Windows-x64.zip`
- `checksums-Windows.txt`

Because v0.1.11 is already public, its tag will be retargeted to the final
source commit before rebuilding. The macOS DMG and checksums will be replaced
alongside the new macOS ZIP, and the Windows files will be added. This keeps the
tag, source archive, displayed application version, and all binaries aligned.

## Verification

Automated packaging tests will cover inclusion of both README files in their
respective archives. Frontend tests will cover Windows detection, POSIX
detection, unknown-platform fallback, manual override, and the exact copied
syntax for both shell families. Existing backend and frontend suites remain
required. The completed GitHub assets will be downloaded after publication,
their checksums validated, and their archive listings inspected before
completion is reported.

## Non-goals

- No visual redesign of the application.
- No change to installation directory defaults.
- No Windows `.exe` installer or Authenticode signing.
- No Intel macOS build.
- No instructions that bypass macOS security protections.
- No new release number; these assets complete v0.1.11.
