# Windows v0.1.11 bilingual README design

## Objective

Publish the existing Windows build as part of release v0.1.11, adding a
bilingual quick-start README inside the ZIP without changing application
behavior.

## Package layout

The root of `OllamaConfigurator-Windows-x64.zip` will contain:

- `README.md`
- `install.ps1`
- `run.ps1`
- `uninstall.ps1`
- `backend/`
- `frontend/`

The build script will copy the README into the staging directory and include it
in the archive explicitly alongside the three PowerShell scripts and the two
runtime directories.

## README content

One Markdown file will contain two complete sections: Portuguese first and
English second. Each section will explain how to:

1. Extract the ZIP to a normal folder.
2. Open PowerShell in that folder.
3. Allow local scripts for the current PowerShell process only.
4. Run `install.ps1`.
5. Run `run.ps1`.
6. Run `uninstall.ps1` if removal is desired.

The commands will use relative paths so they can be copied directly:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\install.ps1
.\run.ps1
```

The README will state that installation defaults to
`%LOCALAPPDATA%\Ollama Configurator`, that port 8787 serves the interface, and
that port 11435 serves the Ollama gateway. It will explain that an existing
Configurator instance may be replaced automatically, while an unrelated
process is preserved and identified for the user.

## Release flow

The Windows workflow remains manually triggered. It will build from the v0.1.11
source state, create the ZIP, and generate `checksums-Windows.txt`. Before upload,
the artifact will be inspected to confirm that `README.md` and all required
runtime files are present. The ZIP and checksum will then be attached to the
existing v0.1.11 GitHub release; the macOS assets remain unchanged.

## Verification

Automated packaging coverage will verify that the Windows build script stages
and archives `README.md`. The existing backend and frontend suites will run
unchanged. The completed GitHub artifact will be downloaded, its checksum
validated, and its archive listing inspected before the release is considered
complete.

## Non-goals

- No application behavior or UI changes.
- No change to installation directory defaults.
- No `.exe` installer or Authenticode signing.
- No new release number; the files are added to v0.1.11.
